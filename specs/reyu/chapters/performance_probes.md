# Performance probes

The executable model is [`performance_probes.ryu`](../models/performance_probes.ryu). This branch describes benchmark and qualification programs; it does **not** add another serving runtime. Every assigned source is experimental, historical, a qualification gate, an evidence harness, or benchmark environment control. Several programs deliberately invoke the production-format banks, vLLM kernels, provider ABI, or a live production-shaped server, but measurement code is not thereby production code.

## 1. High-level design

At breadth-first level the branch is a family of evidence pipelines with a common shape:

```text
arm/config selection
        |
identity + tensor/workload shape admission
        |
functional/numerical precondition (when implemented)
        |
measurement clock and sample window
        |
source-specific aggregation
        |
acceptance gate, advisory observation, or orchestration status
```

There are six measurement boundaries which must not be merged:

1. **Live HTTP serving:** loopback HTTP, SSE parsing, queueing, scheduling, prefill, decode and device work all contribute. Even here, “TTFT” may mean first text-bearing SSE chunk, first arbitrary `data:` line, GuideLLM’s definition, or full non-streamed wall for one output token.
2. **In-process serving:** vLLM engine yields avoid HTTP but still include scheduling, KV management and full model execution.
3. **Isolated kernel/device events:** CUDA or XPU events bracket a kernel call after warmup/synchronization. They exclude the server path.
4. **Native trace analysis:** already-recorded monotonic service intervals or Kineto device intervals are analysed offline. Some sources correlate a request window; others merely take a ring tail.
5. **Host/transport timing:** mmap faulting, CPU staging, host registration, H2D and overlap are separate costs.
6. **Pure CPU/offline decisions:** manifest audits, logprob-array diffs, affine fits, roofline arithmetic and checkpoint-dequantized reference math can be evaluated without running a service.

The model carries `TimingIdentity` and `Aggregation` separately so a median device-event sample cannot silently become a mean HTTP ITL. Its three-sample window is a bounded abstraction: median and mean are calculated exactly for those three fixtures, P90 is conservatively represented by the maximum, and summed/union work by the total. Real sources retain their actual sample counts and formulas below.

## 2. Actors, interfaces and status

| Actor | Interface | Responsibility | Status |
|---|---|---|---|
| Live OpenAI-compatible server | `/health`, `/metrics`, `/v1/completions`, `/v1/chat/completions`, profiling endpoints | Supplies usage counts, streamed deliveries, model outputs and server metrics | External runtime observed by probes |
| vLLM/GuideLLM | Python engine APIs or GuideLLM CLI | Full serving execution and report generation | External dependency |
| CUDA/XPU kernels | Torch, vLLM Marlin, FlashInfer b12x, sgl-kernel-xpu | Candidate grouped-MoE computation and event timing | Production-backed or vendor kernels exercised experimentally |
| Expert banks/checkpoints | SBINT401/Marlin/b12x mmap planes, safetensors | Weight identity, shapes and independent numerical truth | Real artifacts, not generated by this branch |
| Native traces/profiler | JSON ring traces and Kineto trace JSON | Service intervals and device execution categories | Captured evidence analysed offline |
| Shell harnesses | environment, processes, JSON files and manifests | Select A/B arms, boot services, resume or compare | Experimental orchestration |
| [`DummyPoller::loop`](../../../benchmarks/dummy_b70_provider.cpp) | Provider C ABI and signal/completion pages | Immediate zero-fill timing control | Explicitly invalid numerically |
| Operator | [`gpu_power.sh`](../../../benchmarks/gpu_power.sh) | Power/clock envelope | Privileged benchmark control, not measurement |

## 3. Executable state and operations

| Model operation | Source-backed meaning | Preserved distinction |
|---|---|---|
| `selectArm` | A CLI mode, server placement, kernel backend, context/concurrency cell, or shell A/B environment is chosen. | Every arm remains `experimentOnly`; arm selection is not production promotion. |
| `admit(identity, shape)` | Checkpoint/bank provenance and tensor/workload geometry are either verified or assumed by a source. | An assumed constant can be represented as admitted for a scenario, but the chapter records where the implementation never parses the header or digest. |
| `recordSample` | One non-negative timing observation enters a bounded window. | The clock identity remains in state. |
| `aggregate` | Mean, median, high percentile, single sample or accumulated work is reported. | Aggregation is not a quality decision. |
| `assess` | Only coded thresholds become acceptance: b12x bank, Marlin, W4A16, logprob, Laguna, exact-count, manifest and pre-emptive gates. | Descriptive “kill” strings and printed labels are not promoted into gates. |
| `recordAdvisory` | A diagnostic/throughput/layout result is recorded without candidate acceptance. | Finite output is observable but is not proof of numerical fidelity. |
| `finishHarness` | A child succeeds or fails under strict/non-strict shell propagation. | `run_prefill_probe.sh` can finish after a failed child; strict harnesses fail. |
| `missingRequiredControl` | The pre-emptive comparator has no complete null pair. | Missing evidence is not a quality pass. |
| `dummyRelease` | The dummy provider publishes completion after zero fill. | Completion/timing compatibility is explicitly separated from valid model output. |

`gatePass` uses bounded integer observations rather than fixture outcomes: cosine is in ten-thousandths, relative L2 is in thousandths, logprob delta is compared with its supplied tolerance, Laguna uses a milliscale speedup and a failed-check count, exact-count compares observed and required units, the manifest gate accepts zero failed cells, and pre-emptive quality requires a positive peak reduction plus a worst delta no greater than $1.5\times$ the null floor.

## 4. Numerical and kernel-layout probes

### B12x chain

* [`b12x_bank_poc.py`](../../../benchmarks/b12x_bank_poc.py) — `load_bank_layer`, `reference_expert_mats`, and `main` slice real b12x bank planes, independently dequantize checkpoint experts, compare BF16 W4A4 routed SwiGLU with FP32 truth, and then time the real-bank kernel. `--sf-mode bank` uses materialized bank scales; `direct` rebuilds converter-native views. Correctness is enforced at cosine $\ge 0.99$ and relative L2 $\le 0.15$. Timing is one warmup followed by `iters` CUDA-event samples, with only the median emitted. The fixed `synthetic_arm_ms=2.70` is a comparison constant, not a same-run control.
* [`b12x_encoding_probe.py`](../../../benchmarks/b12x_encoding_probe.py) — a fixed top-level diagnostic with no named local function. It quantizes exact checkpoint experts through FlashInfer, compares its bytes with bank bytes and nibble-swapped bytes, and prints cosine/relative L2 for 16 rows. It has no timer and no executable verdict; the prose interpretations are diagnostic hypotheses.
* [`b12x_halfswap_probe.py`](../../../benchmarks/b12x_halfswap_probe.py) — `swap_halves_sf` and `run` compare original gate/up order, simultaneous weight/scale half swap, and alternate down-scale reconstruction. Each arm prints cosine/relative L2; the third arm catches exceptions. No threshold is enforced.
* [`b12x_zero_bisect.py`](../../../benchmarks/b12x_zero_bisect.py) — `arm` cumulatively changes alpha, activation-scale shape and fc2 scale semantics and reports output absolute maximum/nonzero fraction or a caught exception. It has neither truth tensor nor timing nor verdict.
* [`b12x_w4a16_probe.py`](../../../benchmarks/b12x_w4a16_probe.py) — `run` builds checkpoint-native W4A16 weights, ratio-bakes differing gate/up global scales, compares a 16-row BF16 kernel output with exact FP32 checkpoint math, and times seven event samples at $M=8192$. The docstring names cosine and latency gates, but code only prints them; therefore the model treats this file as advisory.
* [`b12x_w4a8_gate.py`](../../../benchmarks/b12x_w4a8_gate.py) — `routed_inputs`, `bank_sf_to_b12x`, `arm_b_their_oracle`, `arm_c_exact`, `arm_a_kernel`, and `main` form a three-arm attribution ladder. B is the vendor W4A8 torch oracle over bank planes, C is exact checkpoint FP32, and optional GPU A is serving-style vendor preparation/execution. `--cpu-only` performs B-versus-C across selected layers without A. The script records rounded scores and a combined B+C wall time but has no coded threshold. The source’s `w31`/pre-swap mutation warning is a real production-integration risk, not an acceptance result from this program.
* [`b12x_bank_poc.py`](../../../benchmarks/b12x_bank_poc.py) is the shared bank/checkpoint anchor used by the smaller diagnostics; sharing a loader does not make their verdict policies identical.

### Marlin and floor modes

* [`marlin_prefill_poc.py`](../../../benchmarks/marlin_prefill_poc.py) — `load_layer_planes`, `dequant_ref`, `cpu_reference`, `to_gpu_marlin`, and `run_marlin` use independent NumPy int4 unpack/dequantization as truth for existing vLLM Marlin. It enforces relative L2 $\le 0.02$ and cosine $\ge 0.999$ before speed measurement. Kernel timing is the median of event samples; H2D+repack is separately wall-timed three times. Serial and pipelined 48-layer projections are derived estimates, not measured forwards.
* [`prefill_floor_bench.py`](../../../benchmarks/prefill_floor_bench.py) dispatches `mode_compute`, `mode_b12x`, `mode_vb12x`, `mode_overlap`, or `mode_register`. `compute` reuses one real layer 48 times; `b12x` times synthetic packed weights; `vb12x` times real planes through vendor helpers; `overlap` contrasts streaming-only, compute-only and concurrent wall times; `register` measures full-bank registration plus spot H2D. Returned kill conditions are strings only. Neither the 7.07 ms incumbent nor degradation/memory prose changes exit status. `mode_b12x` checks finite/nonzero output but has no numerical oracle.
* [`b70_sgl_w4a16_bench.py`](../../../benchmarks/b70_sgl_w4a16_bench.py) — `build_weights`, `naive_moe_ref`, `rotating_routes`, `make_run_fn`, and `run_cell` compare `sgl` or `vllm` XPU grouped W4A16 against a CPU FP32 oracle. The enforced correctness assertion is cosine $>0.999$; relative L2 is recorded. After 300 warmups, five XPU-event windows average 400 calls for $M\le4$ or 100 otherwise; the middle sorted window is reported. Logical routed bytes yield GB/s and percent of a fixed 599.26 GB/s ceiling. At $M=32$, 128 route slots wrap modulo 126 experts, so the broad distinctness description is not literally true even though byte accounting remains $M\times4\times4{,}866{,}048$.

### FP8 wire screen

[`fp8_wire_numerics.py`](../../../benchmarks/fp8_wire_numerics.py) implements `unpack_nvfp4`, `q_e4m3_per_token`, `q_e4m3_blocked`, `metrics`, and `main`. FP32 expert math is compared with BF16 input, shipped FP16 output, candidate FP8 input/output/both, block scales and a two-card partial sum. “SAME REGIME”, “MARGINAL” and “DIFFERENT REGIME” are printed classifications based on error multiples of shipped FP16; they never reject execution. Both labeled combined FP8 partial arms actually quantize each partial separately and are computationally identical, and both serialize under the same `combined:f8` key so the latter overwrites the former. This is a source contradiction, not repaired in the specification. The generic Torch math may be run on CPU where float8 operators are supported; it is still only a plausibility screen, with live combined-logprob qualification required downstream.

## 5. Serving latency and trace probes

* [`b70_itl_probe.py`](../../../benchmarks/b70_itl_probe.py) — `FrequencySampler`, `summarize_frequencies`, and `one_request` sample B70 `act_freq` every 5 ms while issuing serial streamed chat requests. Every nonempty SSE `data:` line except `[DONE]` is timed without parsing JSON/text, so “chunks” are not verified tokens. Request 0 is excluded from aggregate means when possible. Read failures are skipped; missing frequency paths and HTTP/no-chunk failures reject. No output-length or text gate exists.
* [`b70_matrix_probe.py`](../../../benchmarks/b70_matrix_probe.py) — `PromptMint`, `one_request`, `analyse_window`, and `run_cell` cross requested context/concurrency/output cells, make prefix-disjoint prompts, run requests concurrently and correlate device traces whose start timestamp falls within the cell. TTFT/E2E/pooled ITL report count, mean, p50, p90, p99, min and max; throughput uses server completion tokens over whole-cell wall. Missing trace or request failures are recorded rather than fatal. Synthetic prompts are not accepted as evidence for corpus-dependent card balance.
* [`b70_prefill_cost.py`](../../../benchmarks/b70_prefill_cost.py) has two different programs. `analyse_trace` groups native service by actual $M$, takes percentiles and fits unweighted medians to $a+bM$; `chunk_cap_ceiling` evaluates $\lceil T/C\rceil(a+bC)48$, charging the final partial chunk as full. `run_ladder` performs live one-token HTTP requests, excludes a 64-target warmup, groups repeats by actual prompt count and fits wall time against prompt tokens. Prefix-cache deltas are evidence, not a gate.
* [`b70_ttft_smoke.py`](../../../benchmarks/b70_ttft_smoke.py) — `mint` tokenizer-calibrates a corpus prefix; `gate` requires nonempty text and finite selected logprobs for a counting prompt; `ttft` then measures the **entire non-streamed** one-token response, not first-token streaming time. Each context has one unique-header cold request and one identical warm request. Aggregate cold cost is total cold wall divided by total actual prompt tokens. The gate does not verify the counting answer. With one repeat, the prefix-effectiveness check is omitted.
* [`cuda_decode_profile.py`](../../../benchmarks/cuda_decode_profile.py) keeps four identities explicit. `roofline_rows` is CPU lower-bound arithmetic; `completion_request` measures text-bearing SSE TTFT/ITL and enforces exact requested chunk/usage counts; `run_measure` optionally controls profiler start/stop; `analyze_traces` sums classified device event durations and interval unions while excluding wait/write-signal APIs; `compare_runs` subtracts mean live HTTP ITL of dummy from real. That subtraction is exposed end-to-end provider penalty, not native B70 service time.
* [`decode_gap_probe.py`](../../../benchmarks/decode_gap_probe.py) — `decode_steps` groups ring entries with $M=1$ into increasing-layer sweeps of length at least 40 and uses the last 64. It is not request-window correlated, does not verify actual HTTP output length and may include previous traffic. Median service/gap by layer and attention type is heuristic evidence only.
* [`decode_ladder_probe.py`](../../../benchmarks/decode_ladder_probe.py) — `spec_counters` and `main` compare context lengths with random-header approximate prompts. Text-bearing chunk arrivals supply gaps, while server usage supplies output count when present. TPOT uses last-minus-first arrival divided by $n-1$; the reported chunk p50 uses the upper middle and can be burst-distorted. Missing speculative counters become zero; short streams are skipped without failing the program.
* [`prefill_cliff_probe.py`](../../../benchmarks/prefill_cliff_probe.py) — `stream_one` and asynchronous `run` create an in-process vLLM engine for `all-cuda`, `hybrid`, or `all-out`, optionally with prefill streaming. Multi-token engine yields divide the elapsed gap evenly across newly produced tokens. Cells pool request TTFT/ITL and report provider deltas, but neither output count nor content is gated. Request exceptions abort through `asyncio.gather`.
* [`server_context_probe.py`](../../../benchmarks/server_context_probe.py) — `PcieSampler`, `one_request`, and `run` combine HTTP context/concurrency cells with four hard-coded PCIe BDF link-state samples. All requests in a cell reuse the same prompt, so prefix-cache hits are possible. Output token count is text-chunk count rather than usage. Partial/all failures and unreadable sysfs are recorded; there is no PCIe, count, quality or latency threshold.
* [`bench_88b.py`](../../../benchmarks/bench_88b.py) — `Cell`, `build_cells`, `guidellm_command`, `_measurement_is_real`, `run_cell`, and `summarize` build the live 88B GuideLLM grids. A measured cell requires positive measured duration and at least one successful measured request in every report; resume requires return code zero plus `measured=true`. Capacity uses 4,176-token blocks and chat overhead, over-context cells are intentionally skipped, and summaries refuse publication when required measured metrics are absent. GuideLLM owns latency definitions.

## 6. Transport and provider controls

* [`dummy_b70_provider.cpp`](../../../benchmarks/dummy_b70_provider.cpp) implements the provider ABI as a timing control. `DummyProvider::load` validates the first 128 bank-header bytes, version 2, nonzero core dimensions, group 128, 4 bits, zero point 8 and resident-count compatibility. `sb_b70_issue` checks generation/layer/row bounds; `sb_b70_take` zeros output. `DummyPoller::loop` clears a row-count signal, zeroes output for a valid dispatch or increments errors, then publishes completion and counts the dispatch even on its invalid-row/layer path. Service totals and row buckets are real CPU protocol measurements; model outputs are intentionally invalid.
* [`slab_h2d_bench.py`](../../../benchmarks/slab_h2d_bench.py) — `main` assumes, without parsing, a 126-expert slab at fixed 4,866,048-byte stride after a 4 KiB header. It times cold/warm page faults, mmap-to-pinned CPU staging, pinned H2D events, serialized stage+H2D wall, and pageable direct copy. Each transfer arm retains `iters` raw samples plus median/min/max/GiB/s. The 48-layer and ideal-overlap values are projections; there is no byte comparison or acceptance threshold.
* [`hostregister_probe.py`](../../../benchmarks/hostregister_probe.py) — `main` privately maps the same assumed slab, faults pages, registers only the aligned data region and event-times direct H2D. Median/min/max/raw samples, registration/unregistration/fault wall times and first-MiB equality are recorded. Main registration failure is fatal; byte mismatch, throughput, heuristic asynchronous classification and an unexpectedly successful read-only control are not verdicts. The failed read-only control deliberately runs last because it may poison later Torch CUDA operations on the observed driver.
* [`gpu_power.sh`](../../../benchmarks/gpu_power.sh) exposes `status` plus `cap`, `reset`, `clocks` and `unlock` case arms. It re-execs under root, mutates NVIDIA driver controls in non-status modes and takes no sample window. The documented 400–600 W range is not validated; this file controls a benchmark envelope rather than evaluating one.

## 7. Parity, admission and placement experiments

* [`logprob_capture.py`](../../../benchmarks/logprob_capture.py) — `capture` selects generated-token logprobs or prompt logprobs; `diff` requires equal lengths and gates maximum absolute delta against a supplied threshold (default $10^{-3}$). It does not compare model, prompt hash, token IDs, target, mode or generated text, so equal-length captures need external provenance discipline. `diff` is a useful CPU-only implementation comparison.
* [`laguna_gate.py`](../../../benchmarks/laguna_gate.py) — stock-vLLM/CUDA qualification with zero Shooting Brake path involvement. Construction, live prefix-cache enablement, a minimal “42” semantic check, finite selected logprobs and normally $>1.5\times$ cold/warm speedup determine `PASS`. Absolute latency is declared meaningless because weights are CPU-offloaded. Empty logprob collections can satisfy `all`, and one repeat omits the effectiveness check.
* [`laguna_l_sweep.py`](../../../benchmarks/laguna_l_sweep.py) — `kill_server`, `wait_health`, `cold_ttft`, `decode_itl`, and `main` boot one server per local-expert count and record boot, KV, VRAM, cold one-token wall and mean decode ITL. Placement is `fractional:2:L/total`. Failed points and cache-hit warnings do not make the final process fail; error-only rows may not reach JSON until a later success. No optimum is selected.
* [`compare_preemptive.py`](../../../benchmarks/compare_preemptive.py) — `compare_logprobs`, `_worker_field`, `compare_load_peak`, and `main` first require equal non-null `placement`, `config` and `adapter_sha`. Worst-worker load peak must be strictly lower. Quality needs both null controls and worst principal logprob delta $\le1.5\times$ null noise floor. Token equality and KV equality are printed but not acceptance criteria. Missing logprobs yield NaN and fail the quietness comparison.

## 8. Orchestration, resume and failure semantics

* [`ab_register.sh`](../../../benchmarks/ab_register.sh) is the historical registration A/B. It has no shell functions. A nominal “off” boot does not unset an inherited registration variable, a reused server is identified only by health, and `bench_88b.py | tee` lacks `pipefail`. It captures prompt logprobs, three floor modes, registered TTFT and two matrix cells. It leaves the registered server running and produces no manifest.
* [`ab_register_phase2.sh`](../../../benchmarks/ab_register_phase2.sh) defines `boot` and `warm`. It compares registered with nominal off using generated-token logprobs at explicit gate 0.49, after nonfatal warm requests and PSI waiting. The off arm still inherits an ambient registration variable. It uses `set -e` but not `pipefail`, so matrix failures can be masked by `tee`.
* [`chain_audit.py`](../../../benchmarks/chain_audit.py) — `slugify_model`, `cell_state`, and `main` audit a context/profile Cartesian product. Only `run_manifest.json.return_code == 0` is `OK`; missing, corrupt, absent-code or nonzero cells abort. It does not inspect report payloads or manifest identity.
* [`run_preemptive_parity.sh`](../../../benchmarks/run_preemptive_parity.sh) defines `preflight` and `run_one`, launches fresh post-hoc and pre-emptive `offload_benchmark.py` processes, then calls the comparator. The comparator requires both null controls, but this runner supplies neither; therefore its documented successful final comparison is unreachable under the current source seam.
* [`run_prefill_probe.sh`](../../../benchmarks/run_prefill_probe.sh) defines `run_arm` for hybrid, all-CUDA and hybrid-with-streaming. Any existing file is treated as cached success without JSON/identity validation. Because the script omits `set -e`, a failed Python child is followed by successful `echo`/`sleep`, and the script normally reaches `ALL ARMS DONE`. The model’s `maskedChildFailure` witness preserves this contradiction.
* [`run_guidellm_context_benchmarks.sh`](../../../benchmarks/results/rtx_pro_6000_r15_slo/run_guidellm_context_benchmarks.sh) defines `run_command` and `run_profile` for 24 context/profile cells. Skip-existing requires nonempty JSON **and** CSV but validates neither identity nor status. Dry run still creates directories. Strict shell failure propagation applies outside dry run; the `prefix_cache=disabled` label is metadata only and does not configure or verify the server.
* [`run_prefill_probe.sh`](../../../benchmarks/run_prefill_probe.sh) invokes [`prefill_cliff_probe.py`](../../../benchmarks/prefill_cliff_probe.py); their completion rules differ and must be considered together.

## 9. Executable scenarios and properties

The model provides reachable, named witnesses:

* `b12xBankSuccessTest` admits a numerical/device-event arm, calculates a three-sample median of 11, and passes the implemented 0.99/0.15 gate.
* `marlinQualityFailureTest` demonstrates that acceptable relative L2 cannot compensate for cosine below 0.999.
* `advisoryFp8ScreenTest` records a finite screen without creating an acceptance result.
* `exactSseCountFailureTest` separates measured mean gap from an exact-delivery-count failure.
* `chainAuditSuccessTest` accepts only zero failed manifest cells.
* `preemptiveRunnerMissingNullTest` makes the shipped runner/comparator prerequisite mismatch reachable.
* `prefillHarnessMasksChildFailureTest` and `strictHarnessPropagatesFailureTest` distinguish non-strict from strict shell behavior.
* `dummyCompletionIsNotCorrectnessTest` makes a completed but invalid zero partial reachable.
* `shapeAdmissionFailureTest` rejects an assumed transport geometry when the scenario marks it invalid.

`inv` bounds the sample window, requires accepted outcomes to be checked/valid, requires aggregation to have samples, and preserves the experimental classification. It does not claim floating-point equivalence, timing determinism, hardware progress or shell/process equivalence.

## 10. Implementation comparisons and limits

Useful CPU-side comparisons are:

* `b12x_w4a8_gate.py --cpu-only`: bank W4A8 oracle versus exact checkpoint FP32 across layers.
* `marlin_prefill_poc.py::dequant_ref` / `cpu_reference`: independent int4 bank truth for a GPU kernel output.
* `b12x_bank_poc.py::reference_expert_mats`: checkpoint-derived truth independent of bank bytes.
* `fp8_wire_numerics.py`: generic Torch round-trip/error math on CPU where float8 support exists.
* `logprob_capture.py::diff`: pure array-delta gate, provided provenance is checked externally.
* `compare_preemptive.py`: pure JSON identity/noise-floor/load-peak decision.
* `chain_audit.py`: pure manifest structural audit.
* `b70_prefill_cost.py::_fit_affine` / `chunk_cap_ceiling`, `cuda_decode_profile.py::roofline_rows` / `analyze_traces`, and trace percentile helpers: deterministic offline calculations over fixtures.

Hardware-bound claims still require their actual environment: CUDA/XPU event timing, registered memory, PCIe state, GPU power control, live vLLM/GuideLLM service, real banks and checkpoints, or native traces. A model run can check the abstraction’s transition logic; it cannot establish performance, kernel fidelity, transport coherency, checkpoint provenance or production promotion.
